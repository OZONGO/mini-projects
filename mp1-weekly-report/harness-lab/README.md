# Harness Lab：MP1 上的弱/强 harness 对照实验

## 1. 实验问题

同一个被试（确定性假 agent）、同一个任务，只变 harness 侧的家当：
弱侧＝一段自然语言任务描述；强侧＝AGENTS.md ＋ feature_list.json ＋ check.py。
同样的缺陷产物，是弱侧当"完成"收货，还是强侧拦在门口？

## 2. 被试与任务（方向甲）

- 被试：`fake_agent.py`——确定性脚本，零背景知识，两轮一字不改。
- 任务：产出 W2 学习周报的 JSON 数据文件 `week_report.json` 并报告完成。
- 被试实现方式：不走 `generator.py` 的 JSON 导出，自行取聚合结果交货
  （缺陷＝裸 `json.dumps`：吐 array 不吐 object、中文转义——2026-09-24 本人
  探针实测过的 MP1 真实契约，在此充当实验道具）。

### 2.1 申报缺陷清单（＝ check.py 断言清单）

申报清单＝断言清单，不许任何一项"报而不检"或"检而不报"。

- **D1 · 形状违规（初版申报）**：裸 `json.dumps` 之下，`week_items` /
  `category_items` 由 list[object] 退化成 list[array]，且顶层若被误写为
  list 则连 object 都保不住。
- **D2 · 编码违规（初版申报）**：`ensure_ascii` 默认 True，中文键（语法/
  项目/复习/文档）以 `\uXXXX` 转义落盘，而非 UTF-8 原文。断言方式是
  **读产物原始字节**：`语法` 的 UTF-8 原文在场、`\u8bed` 转义不在场——
  纯字符层判据，不受 json 解析后视图影响。
- **D3 · 范围违规（读产物发现后升格为申报缺陷）**：弱轮实测产物
  `week_items` 含 W1/W2/W3，是全量报告，而任务要求的是 W2 周报。
  这一条**不在初版申报中**，是 S2 判卷时打开产物、对着任务描述核对该
  发现的——按"申报清单＝断言清单"的纪律，它现在升格为申报缺陷，并由
  `check.py` 断言。

### 2.2 子裁决留痕：形状缺陷的两个面

D1（array/object）与 D2（中文转义）是同一行 `json.dumps` 的两个后果。按
A 论证的口径"申报了的就该被断言"，两面**都进判据**——不存在"报了 D1 却
把 D2 挂在申报栏里当装饰"的写法。

## 3. 两轮流程

| 轮次 | harness 家当 | 流程 |
|---|---|---|
| 弱轮 | `weak/task-prompt.md`（仅此一件） | 被试按提示词执行 → 自行宣布完成 → 记录输出与产物 |
| 强轮 | 同一被试＋`strong/` 三件 | 被试执行（产物应与弱轮相同）→ 运行 `check.py` → 记录拦截证据 |

纪律：被试两轮一字不改；检查全部住 harness 侧；**两轮起点一致——每轮开跑前
删除上一轮的 `week_report.json`**（防起点污染）。

> 无效尝试（本人自报、未留输出，不进证据链）：① 强轮一次 debugpy launcher
> 连接被拒（端口无人听、脚本未加载，退 1）；② 修前 `check.py` 曾在产物缺失时
> 退 2——输入不可读分支按设计生效过一次，只是没留下输出。

## 4. 指标表（实测；强轮见下注）

| 指标 | 定义 | 弱轮 | 强轮 |
|---|---|---|---|
| 完成状态 | 完全完成 / 部分完成 / 失败 | 完全完成（自宣布） | 失败（check.py 退 1） |
| 退出信号 | 被试 / 验证进程的退出码 | 被试 exit 0 | 被试 exit 0；check.py exit 1 |
| 遗漏项 | feature_list 判据未过的条目 | 不适用（无清单） | D1b（week_items）、D1b（category_items）、D2、D3；D1a 与 MP1 测试套件过 |
| 过早停止（假通过） | 宣布完成时存在未检出的违规 | 是（D1b/D2/D3 全未检出） | 否（同批违规被 check.py 具名拦截） |
| 拦截证据 | check.py 红在哪条判据 | 不适用 | D1b×2 / D2 / D3 四条 FAIL，诊断含原形 |

> 注 1：弱轮"退出信号"实测 exit 0（`fake_agent.py` 的 `main()` 返回 0）。
> 注 2：**强轮列性质 = 实测**——锚定 2026-09-25 强轮重跑（删产物 → 被试 →
> 修复版 `check.py`，本人终端：退 1、4 刀 FAIL、逐行输出在案）。**唯一推出值
> 是"产物字节两轮相同"**（确定性被试＋一字不改；弱轮产物按协议已删、未对字节、
> 未留 hash）。原注曾把强轮列误标"推出值、非本轮实测"，与在案 transcript 冲突，
> 经本人重跑实测后订正（2026-09-25 教练代改，本人授权"你来进行readme的修改"）。

## 5. 结论

同一位确定性被试、同一份 `sessions.md`，仅切换 harness 侧家当。产物字节两轮
相同（**推出值**：被试一字未改＋确定性；未对字节、未留 hash），差别只发生在
"门口有没有人查"。

- **弱轮**：产物落盘、进程退 0、打印"任务完成：…week_report.json"。系统内
  没有任何机制看见产物身上的三处契约违规（形状退化成 array、中文被转义、
  范围是全量）。**这不是"没检测"，是"检测这件事在这个配置里不存在"**——
  表面完成信号与真实契约之间没有桥。
- **强轮**：被试行为逐字不变，但 `check.py` 以退出码 1 拦下产物，并逐条指认
  红在哪条判据（D1b×2 / D2 / D3）。同批违规从"无人可见"变成"具名拦截"。

这就是反馈子系统"检测→判定接通"的拦截价值的直接演示：**有后果的检查才叫反馈。**

### 5.1 元层留痕：本实验的 checker 自己犯过两病

实验过程中，`check.py` 初版各犯一次：

- **诬报**：拿课程模板的 `pytest` 当项目尺子 → 误报"套件未过"；且 tail 只裁
  `stdout`、把 `stderr` 上的真凶（`No module named pytest`）裁掉，把"启动器
  不对"报成"套件红"。**反馈子系统对全绿系统喊红——红的公信力被消耗。**
- **伪证**：D3 的提取管线静默滤掉 array 条目，报"实际含：[]"，把"我没看见"
  报告成"不存在"。**FAIL 判对了，证据撒了谎。**

两病都在"证据→判定"链上断裂：弱 harness 的病是"看见了不算"（检测端断链），
坏 checker 的病是"对着捏造的所见下判"（证据端断链）——同一条链的两头。修复
方向由本项目既有纪律给出：验证命令用**本项目自己的尺子**、错误信息 **stdout
与 stderr 全带出**、诊断**要么报真相、要么承认"无法提取"**。

由此补出反馈子系统的完整质量线，比"零沉默型变异"更完整：

> **零沉默（不漏报）＋ 零诬陷（不误报）＋ 零伪证（不伪造证据）。**

这条质量线本身，是人在环（教练读码）抓出来的——**反馈子系统的质量，也需要反馈。**

### 5.2 范围声明

本实验演示反馈子系统的**拦截价值**（检测→判定接通后，缺陷被拦在门口，且红点
指认违规类型）。它**不**演示强 harness 的另一半价值——agent 读取 AGENTS.md、
运行验证命令后的**自我纠错**——确定性被试没有学习能力，那一半需要真 agent 才
测得到。
